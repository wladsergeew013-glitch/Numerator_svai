# Данные, перенос и локальный API

EXE хранит `projects`, `config`, `autosaves`, `data` и `logs` рядом с программой. В исходном запуске корнем служит репозиторий. Переменная `PILE_NUMBERING_DATA_DIR` задаёт другой постоянный корень до создания API. У frozen-сборки все пути, включая ICO и автосохранение, задаёт один `RuntimePaths`.

Docker Compose использует именованный том `pile_data`, смонтированный в `/data`, и `PILE_NUMBERING_DATA_DIR=/data`. Пересоздание контейнера сохраняет проекты, recent list, настройки и autosave. Не удаляйте том командой `docker compose down -v`, если в нём есть нужные данные. Порты публикуются только на `127.0.0.1`.

## Резервная копия и восстановление

Закройте экземпляры программы и остановите контейнер перед переносом данных. Скрипт работает с каталогами данных и не заменяет отличающиеся существующие файлы. Восстановление в пустую папку позволяет проверить копию до переключения установки.

```powershell
backend/.venv/Scripts/python.exe tools/10_data_backup.py backup "D:/PileNumber" "D:/Backups/piles.zip"
backend/.venv/Scripts/python.exe tools/10_data_backup.py restore "D:/Backups/piles.zip" "D:/PileNumber-restored"
backend/.venv/Scripts/python.exe tools/10_data_backup.py migrate "D:/PileNumber-old" "D:/PileNumber-new"
```

Для старого контейнера сначала остановите его, затем скопируйте существующие `/projects`, `/config`, `/autosaves` и `/data` в отдельную папку на хосте командой `docker cp`. Старый контейнер и его папки сохраняйте до проверки копии. Сведите содержимое в структуру указанного корня и примените `migrate` в пустую папку. Её можно временно смонтировать как `/data`; после проверки перенесите те же каталоги в именованный том. Не копируйте данные из корня хоста автоматически: прежний путь `/projects` относился к файловой системе контейнера.

## HTTP-клиенты

Все пути `/api`, включая GET со сканированием и выбором папки, требуют ключ локальной сессии. Клиент получает его через `POST /api/session` с заголовком `X-Pile-Client: 1`, затем передаёт `X-Pile-Token`. Ключ случайный и меняется при перезапуске backend. Ответ handshake запрещён для чужого Origin; браузер дополнительно получает HttpOnly SameSite=Strict cookie для иконок и связанных окон. Секрет не передаётся в URL и не записывается в журналы.

Разрешены тот же origin, с которого работает EXE, и адреса разработки `http://localhost:5173` / `http://127.0.0.1:5173`. Host и адрес клиента должны быть loopback. Используйте одинаковое написание хоста для Vite и API, чтобы cookie изображений оставалась в том же сайте. Vite и исходный backend по умолчанию слушают loopback; внутри контейнера используется `0.0.0.0` с публикацией порта на loopback хоста. Только для внутреннего Docker proxy включён `PILE_NUMBERING_TRUST_CONTAINER_PEERS=1`, допускающий private peers контейнерной сети; этот параметр не следует включать у сервиса, доступного по сети.

Граница защищает от постороннего сайта и случайного открытия сервиса в локальную сеть. Процесс, уже выполняющийся от имени пользователя на его компьютере, относится к доверенному локальному окружению. Для сетевой многопользовательской установки нужны отдельная аутентификация и политика доступа; этот режим не включается изменением `--host`.

Общее тело запроса ограничено до разбора: 16,2 МБ, для иконок — 2,1 МБ с учётом multipart. Сам CSV ограничен 16 МБ и 100 000 точек; импорт таблиц — 100 000 строк и 256 колонок. Неподдерживаемый urlencoded отклоняется до парсера. JSON-ошибки содержат имя поля, CSV-ошибки — строку. Excel разбирается в отдельном worker с лимитом времени; отмена завершает worker.

Пользовательские иконки хранятся в `config/icons`. Растровые файлы декодируются с ограничением размеров и сохраняются как PNG; SVG допускает только графические элементы без внешних ссылок и активного содержимого. Удаление файла снимает сохранённые привязки; недоступная иконка заменяется стандартной.

## Связи с CAD

Сохранённый handle требует совпадения пути и `FINGERPRINTGUID` базы DWG. Для старого проекта без GUID выполните новый скан и явный импорт: совпадающая старая связь получит GUID с сохранением ID, номера и группы точки. Снимки скана дополнительно относятся к текущей сессии backend. После попытки записи снимки инвалидируются независимо от результата. Экспорт использует только итоговый `number`; точки без номера учитываются отдельно как пропущенные.

Закрытие EXE останавливает приём новых CAD jobs, запрашивает отмену, ждёт worker и подтверждение native-команды либо её deadline. Статусы и частичные счётчики сохраняются в `logs/cad-shutdown.json`. Если завершение ещё не подтверждено, окно остаётся открытым с сообщением. Временный request и cancellation marker сохраняются до acknowledgement/deadline. Реальная приёмка COM/NRX, отмены во время записи и повторного открытия DWG остаётся отдельной процедурой на nanoCAD.
