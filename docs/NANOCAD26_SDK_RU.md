# Обмен с nanoCAD 26 через SDK

В проблемном окружении подключение к документу и чтение `ModelSpace.Count` проходили, но первая попытка `ModelSpace.Item(0)` завершалась ошибкой TeighaX «Не найдена указанная процедура», внутренний HRESULT `0x8007007F`. До чтения свойств объектов Model Studio исполнение не доходило. Это подтверждало отказ пути преобразования объектов COM в данном окружении; конкретная несовместимая DLL не была установлена, и это не доказывает удаление всего COM API в nanoCAD 26.

Для nanoCAD 26 коллекции чертежа читает NRX-модуль `PileNumbering.Sdk26.nrx`, собранный с SDK nanoCAD `26.0.7714.4962.8915` и публичными интерфейсами Model Studio 7680. Доступ к параметрическим объектам идёт через `GetMStudioDataInterface`, `IFactoryInterface.CreateParametricWrapper`, `IParametricEntWrapper.GetPosition` и `GetParametersRoot`. Здесь нет обхода `TeighaX.ModelSpace.Item`, преобразования объектов через IDispatch или вручную рассчитанных адресов виртуальных методов.

COM сохраняется для присоединения к уже запущенному CAD, управления документом (имя, регенерация, отдельно разрешённое сохранение DWG) и отправки команды SDK. Он также остаётся прежним способом обмена с более ранними версиями nanoCAD. Подмена внешнего соединения или автоматический запуск другой версии CAD не выполняются.

## Использование

1. Откройте nanoCAD 26 с загруженным Model Studio и нужный DWG.
2. В нумераторе выберите nanoCAD 26 либо автоматический поиск.
3. Запустите сканирование Model Studio. Модуль находится внутри EXE и извлекается в отдельную папку по хешу в `%LOCALAPPDATA%\PileNumbering\sdk`; CAD загружает его командой `arxload`. Имя файла и команды содержит хеш сборки, поэтому новая версия не вызывает команду ранее загруженного модуля.
4. Если CAD требует ручного разрешения загрузки, загрузите указанный в журнале `PileNumbering.Sdk26.<хеш>.nrx` через `APPLOAD`. После этого повторите сканирование. Активная команда CAD должна быть завершена.

Запрос выполняется в командном контексте CAD, а не в фоновом потоке, работающем с базой чертежа. Выделение и весь ModelSpace читаются через NRX. Координаты, параметры, handle и атрибуты возвращаются в нумератор через временный файл. Импорт продолжает использовать прежнюю логику базовой точки, групп и нумерации. Скан и импорт не сохраняют DWG и открывают исходные сущности только для чтения. Поскольку `GetParametersRoot` не объявлен `const` в SDK, дерево параметров при чтении получается у отдельного, не добавленного в базу клона объекта.

Запись номеров использует тот же SDK: существующий параметр изменяется через публичный интерфейс и `UpdateData`, после чего значение читается обратно. При ошибке SDK другие варианты COM-записи автоматически не пробуются. Прежняя отдельная настройка сохранения DWG действует при экспорте.

Каждый запрос проверяет исходный документ и срок действия; истёкшая или отменённая команда не должна менять другой DWG после задержки в очереди CAD. Новые этапы журнала: `cad_sdk_transport`, `sdk_bridge_started`, `sdk_bridge_completed`.

Текущее выделение захватывается через `ssget "_I"` до загрузки NRX и запуска служебной команды. Для скана выделенных объектов в файл запроса передаются только handle этого набора; сущности, координаты и параметры читает SDK после проверки документа. Команда не пытается заново получить PICKFIRST после запроса пути, когда CAD уже может очистить его. После завершения служебной команды исходное выделение восстанавливается через `sssetfirst`; приложение ждёт подтверждения завершения этого шага. Это действует также для полного скана и определения нового DWG. В журнале `sdk_selection_snapshot` показывает `capturedCount`, `objects`, `source=pre-command`, `selectedBeforeCommand`, `selectedAfterCommand` и `selectionRestored`. Пустое текущее выделение не заменяется предыдущим набором; отсутствующий или повреждённый снимок даёт ошибку.

Несохранённый DWG проверяется по GUID базы, а при первом обращении без доступного GUID через COM — по имени текущего документа SDK с последующим получением GUID. Пустой файловый путь нового чертежа не сравнивается с отображаемым именем «Без имени0». Снимок скана и связи с объектами несохранённого документа используют ключ `unsaved:<GUID>`; другой новый чертёж с таким же именем не получает старый снимок.

## Сборка

Нужны Visual Studio C++ v143, Windows SDK, компоненты ATL/MFC, SDK nanoCAD 26 и SDK Model Studio. Заголовки и библиотеки поставщиков в репозиторий не копируются.

```powershell
tools/09_build_sdk_bridge.ps1 -NanoCadSDK "D:/repo/SDK/Nanocad/26.0.7714.4962.8915" -ModelStudioSDK "D:/repo/SDK/MS/7680/Model Studio"
tools/06_build_exe.bat
```

Пути также задаются переменными `PILE_NUMBERING_SDK26_DIR`, `PILE_NUMBERING_MS_SDK_DIR`, `PILE_NUMBERING_ATLMFC_DIR`. Необязательный параметр `AtlmfcDir` указывает каталог с подкаталогами `include` и `lib/x64`, если компоненты MFC расположены отдельно. `06_build_exe.bat` пересобирает модуль перед упаковкой, а спецификация PyInstaller требует его наличия. Версии SDK и SHA256 записываются в `cad_bridge/bin/nanoCAD26/build-info.json`.

## Граница проверки

Сборка NRX и тесты Python проверяют соответствие заголовкам SDK, протокол, маршрутизацию версии, преобразование данных, импорт и запись с чтением результата обратно на имитации SDK. Они не заменяют загрузку NRX и полный цикл на реальном nanoCAD 26 / Model Studio 7680. Для проверки записи следует использовать отдельную копию DWG; исходный чертёж менять не требуется.
