# Нумератор свайного поля

Иллюстрированное руководство пользователя описывает импорт из Excel и nanoCAD, работу с группами, нумерацию, проверку и запись номеров в DWG. 17 страниц и 27 снимков интерфейса. [PDF](docs/PileNumbering_User_Guide_RU.pdf) · [Word](docs/PileNumbering_User_Guide_RU.docx)

## Исправления обмена и авторазбивки, сентябрь 2026

- Актуальный EXE находится только в `dist/PileNumbering.exe`. Сборка: `tools/06_build_exe.bat`, единая переносимая конфигурация — `tools/PileNumbering.spec`. Данные прежних тестовых сборок сохранены в `data/previous-builds`; рабочие проекты остаются в `dist/projects`.
- Ранняя заставка PyInstaller появляется при распаковке EXE и показывает этапы запуска до готовности интерфейса. Изображение `tools/splash.png` воспроизводится скриптом `tools/create_splash.ps1`.
- При закрытии EXE с несохранёнными изменениями появляется диалог «Сохранить / Не сохранять / Отмена». Сохранение открывает выбор файла; отмена или ошибка записи оставляют приложение открытым. Файл заменяется атомарно после записи временного файла. В браузере используется стандартное предупреждение перед закрытием вкладки. Перемещение камеры и выделение не считаются изменением данных поля; возврат к сохранённым данным через Undo снимает признак изменений.
- Диспетчер: закреплённые пайплайн и команды, состояния нумерации слева (готово / частично / нет номеров / пусто), команда нумерации у каждой группы. Повторный клик снимает выбор. Двойной клик или «О группе» открывает отдельное перемещаемое окно сведений и настроек. «Порядок» без выбранной группы показывает маршруты всех видимых групп. Двойное нажатие средней кнопки мыши вызывает «Всё поле».
- Область модели учитывает фактические размеры закреплённых окон. Оси и легенда остаются внутри свободного пространства. При движении курсора тяжёлые панели не перерисовываются; поиск групп и точек использует индексы, объекты вне экрана пропускаются при отрисовке. Режим «Без номера» рисует уже пронумерованные точки упрощённо, сохраняя выбор мышью.
- «Номера групп» показывает на схеме порядок группы независимо от её имени. В диспетчере имя и позиция редактируются отдельно: ввод занятой позиции вставляет группу на неё и сдвигает остальные. Настройки выбранной группы закреплены при прокрутке; информация о точке выбирает её группу в диспетчере. Старые автоматически включённые границы групп отключаются при миграции настроек; явное последующее включение сохраняется.
- Статус сканирования показан в блоке поиска и автоматически выводится в видимую область. Команда импорта/экспорта и отдельный результат находятся в закреплённом блоке. При нулевой записи экспорт явно сообщает об этом.
- Проверенный файл `4210_1-2_МЕЖЦЕХОВКА.pilenum.json` с E: содержит 911 точек, пустой список групп, без назначенных `groupId` и итоговых номеров. Пустой диспетчер соответствует содержимому этого файла; исходник не изменялся.
- Авторазбивка использует относительные расстояния, учитывает близкие пары свай и не объединяет удалённые поля только из-за общего ряда. Перед применением показывает количество и размеры групп; радиус объединения можно изменить. Заблокированные точки и группы сохраняются.
- В диалоге доступны связанные участки, ветви и разрывы, ряды и полосы, HDBSCAN, DBSCAN, OPTICS и заданное число групп. Предпросмотр показывает распределение и неназначенные точки; результат применяется одной отменяемой операцией. Изменённые после расчёта точки требуют нового предпросмотра. Расстояния нормализуются единым масштабом, без растяжения осей по отдельности. Подробности: [методы и ограничения](docs/AUTO_CLUSTER_REVIEW_RU.md).
- Импорт добавляет новые точки без замены готовых номеров, координат и групп. Повторные точки пропускаются; близкие, но разные точки не объединяются с допуском 1 единица. При наличии handle различаются и объекты с одинаковыми XY.
- Сканирование/импорт/экспорт: выделенные объекты nanoCAD, весь чертёж или автоматический выбор области. Если выбрано «Только выделенные», пустое выделение даёт ошибку, а не переход к целому чертежу. COM-адаптер использует текущее `PickfirstSelectionSet`; доступность проверяется во время выполнения. Смысл свойства описан в [справочнике ActiveX](https://help.autodesk.com/cloudhelp/2026/DEU/AutoCAD-ActiveX-Reference/files/GUID-D48A1C37-4223-4AAA-B1DC-A746604C49B3.htm).
- Опционально при импорте Model Studio сохраняются handle и путь исходного DWG в `point.meta`. Копии точек не наследуют связь. Ускоренный экспорт сначала проверяет handle, остальные точки ищет по координатам. Доступны также отдельные режимы координат и только handle.
- Предварительный поиск типов и параметров при экспорте Model Studio необязателен и не создаёт кеш для последующего экспорта. Если имя параметра известно, экспорт можно начинать сразу. Ограничение по типам включается отдельно и действует также при поиске по handle. Допуск задаётся в единицах чертежа.
- Операции nanoCAD выполняются последовательно, с COM-инициализацией и освобождением в одном рабочем потоке. Фоновые операции доступны через `POST /api/nanocad/operations` и `GET /api/nanocad/operations/{id}`; прежние endpoints сохранены.
- Прогресс показывает фактически обработанные объекты. В `logs/backend.log` записываются идентификатор операции, область, документ, этапы, длительность, результаты записи и ошибки. При обрыве RPC экспорт не повторяется автоматически: часть значений уже могла быть записана.
- Запись параметра считается успешной после чтения значения обратно. DWG сохраняется только при включённой опции сохранения и отсутствии ошибок записи; ошибка сохранения показывается отдельно от результатов записи.
- Компактная CAD-лента, единые контурные значки, пояснения при наведении и фокусе клавиатуры. Указатель X/Y расположен в начале координат, а когда начало за экраном — в левом нижнем углу; его размер не зависит от масштаба.
- Отдельный визуальный слой «Связи групп» (лента «Настройки» → «Рабочее поле» или настройки маркеров): голубые кольца стартов, оранжевые кольца финишей, пунктирные стрелки к следующей группе в каждом пайплайне. Концы берутся из маршрута по текущим настройкам и ручным ограничениям. Пустые группы пропускаются; скрытые не соединяются обходной связью. Слой не меняет нумерацию и ручные связи, размер обводок постоянен на экране.
- Диспетчер: компактный список групп и настройки выбранной группы со схемами методов. Все настройки можно раскрыть в общем списке. Ряды идут вдоль X, столбцы — вдоль Y; исправлены направления змейки и повтор точек при старте из середины поля. Для новых групп допуск подбирается по шагу точек; существующим доступна кнопка подбора.

В настройках рабочего поля на вкладке **nanoCAD** можно выбрать версию, включая **nanoCAD 26**. Выбор сохраняется в `config/user_config.json` и действует при следующем подключении. Если выбранная версия или её открытый чертёж недоступны, обмен останавливается с предупреждением и кнопкой **Открыть настройки nanoCAD**, которая сразу открывает нужную вкладку. Другая версия автоматически не используется. Режим «Автоматически» сохраняет прежний поиск среди запущенных версий. Переменные `PILE_NUMBERING_NANOCAD_PROGID` и `PILE_NUMBERING_NANOCAD_VERSION` имеют приоритет над выбором в настройках.

В nanoCAD 26 обход объектов перенесён в NRX-модуль SDK, встроенный в EXE: он читает чертёж, координаты и параметры Model Studio без `TeighaX.ModelSpace.Item`. COM сохраняется для связи с открытым окном CAD и для предыдущих версий. Порядок работы, сборки и границы проверки описаны в [инструкции SDK](docs/NANOCAD26_SDK_RU.md).

Скан выделенных объектов захватывает набор до запуска служебной команды CAD. После команды исходное выделение восстанавливается; журнал показывает количество выбранных объектов до и после неё. Чтение сущностей и параметров остаётся в SDK. Пустой набор не подменяется предыдущим выделением или всей моделью в режиме «Только выделенные».

Крестик закрывает панель за одно нажатие; кнопка возврата восстанавливает прежнее закрепление. ## Быстрый запуск в VS Code

1. Установите Python 3.12 или 3.13 x64, Node.js 22.12+ (или 24 LTS) и расширения Python и Python Debugger для VS Code.
2. Откройте корень клона в VS Code через `code .` или **File → Open Folder**.
3. В **Run and Debug** выберите **Нумератор свай (backend + frontend)** и нажмите **F5**. Задача подготовит `backend/.venv` и установит frontend-зависимости по lock-файлу.
4. Откройте `http://127.0.0.1:5173`. Backend работает на порту 8000. Для остановки обоих серверов нажмите **Shift+F5**.

Для работы с файлами SDK не требуется. Для сборки моста nanoCAD 26 укажите расположение SDK по [инструкции](docs/NANOCAD26_SDK_RU.md). Лог подготовки окружения находится в `tools/out/run_dev.log`.

## Локальная папка проектов

Backend автоматически создаёт папку `projects/` в корне проекта.
Через кнопку `Проекты` на верхней панели можно:

- сохранить текущий `.pilenum.json` в `projects/`;
- увидеть список сохранённых проектов;
- быстро открыть проект из списка.

Обычные кнопки `Открыть` и `Скачать` также остаются: они работают через стандартный выбор файла браузера.

## Автоматическое сохранение настроек интерфейса

Настройки рабочего поля сохраняются автоматически в локальный конфиг браузера (`localStorage`): фон, сетка, оси, цвет текста нумерации, положение диспетчера групп, режим автоназначения и последнее имя проекта. При следующем запуске нового проекта эти настройки применяются автоматически.

Рабочий файл `.pilenum.json` всё равно хранит собственные настройки проекта, поэтому открытый проект переносит с собой фон, сетку и параметры отображения.
